# 주석 / 문서 작성 컨벤션

## 기본 원칙

- 모든 주석은 한글로 작성한다. 코드의 변수명, 함수명, 클래스명 등 식별자는 영문으로 작성한다.
- 주석은 What이 아닌 Why를 설명한다. 코드만 읽어도 알 수 있는 내용은 주석으로 반복하지 않는다.
- 한 줄 주석은 //, 여러 줄 설명은 KDoc(/** */)을 사용한다.
- 코드만으로 알기 어려운 의도, 트레이드오프, 제약 사항, 단위, 근거, 엣지 케이스 등을 남긴다.

---

## 주석 작성 기준

### 클래스

- 클래스의 역할과 책임을 한두 문장으로 작성한다.

### 메서드

- 메서드명과 시그니처만으로 의도가 명확하면 주석을 생략한다.
- 비직관적인 동작, 부수 효과, 호출 시점 제약, 성능상의 고려 사항만 간결하게 작성한다.

### 필드 / 상수

- 필요한 경우 단위, 목적, 근거를 // 인라인 주석으로 작성한다.

### 인라인

- 비직관적인 구현이나 의사결정의 이유만 짧게 작성한다.
- 추가 설명이 필요하면 —(대시)로 이어서 작성한다.

---

## 주석 작성 시 금지 사항

- 코드를 그대로 설명하거나 반복하는 주석
- 사용하지 않는 주석 처리된 코드 방치
- 코드와 맞지 않는 오래된 주석 방치

> 코드가 변경되면 주석도 함께 수정하거나, 더 이상 필요하지 않다면 삭제한다.

# 설명 글 / 문서 작성 컨벤션
(예: PR 설명, 코드 리뷰, 설계 문서, 리포트)

## 기본 원칙

- 결론(요약)을 먼저 작성하고, 근거와 상세 설명을 뒤에 작성한다.
- 여러 선택지가 있다면 중요도순으로 정렬하고, 가장 추천하는 방식을 맨 위에 배치한다.
- 트레이드오프가 있다면 장단점과 함께 해당 방식을 선택한 이유를 명확하게 설명한다.
- 문서는 핵심만 간결하게 작성하되, 의사결정에 필요한 근거는 생략하지 않는다.
