# 커밋 컨벤션

## 커밋 메시지 형식

<타입> <한글 설명>

### 타입

- feat: 새로운 기능 추가
- fix: 버그 수정
- refactor: 동작 변경 없는 내부 구조 개선
- chore: 빌드, 설정, 의존성 등 유지보수 작업
- docs: 문서 작성 및 수정
- test: 테스트 코드 작성 및 수정

### 작성 규칙

- 제목은 50자 이내로 작성한다.
- 제목은 명확하고 간결하게 작성한다.
- 제목 끝에 마침표를 사용하지 않는다.
- 설명은 반드시 한글로 작성한다.
- 본문은 필요한 경우에만 작성하며, 무엇을 변경했고 왜 변경했는지를 중심으로 작성한다.

### 예시

bash git checkout -b feat/aaa  git commit -m "feat bbb 기능 구현"

# 커밋 단위

- 하나의 커밋은 하나의 논리적 변경만 포함한다.
- 하나의 커밋은 독립적으로 리뷰 가능해야 한다.
- git revert 시 하나의 변경 사항만 되돌릴 수 있어야 한다.
- 하나의 기능을 구성하는 관련 파일(예: Controller, Service, Repository)은 같은 커밋으로 묶는다.
- 서로 다른 목적의 변경은 커밋을 분리한다.

# 브랜치 컨벤션

## 기본 규칙

- 모든 작업 브랜치는 main에서 생성한다.
- 브랜치명은 영문 소문자를 사용한다.
- 단어는 하이픈(-)으로 구분한다.

## 네이밍

- feat/기능명
- fix/버그명
- refactor/대상
- chore/내용
- docs/문서명
- test/대상

### 예시

- feat/aaa
- fix/bbb
- refactor/ccc
- docs/ddd
- chore/eee

---

# PR

- 작업이 완료되면 main 브랜치를 대상으로 PR을 생성한다.
- PR 제목과 설명은 한글로 작성한다.
- 변경 내용, 변경 이유, 트레이드오프가 있다면 선택한 이유를 함께 작성한다.
