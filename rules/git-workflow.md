## 커밋 및 PR 생성 컨벤션

### 작업 규칙

* main 브랜치에 직접 커밋하거나 푸시하지 않는다.
* 커밋 전에 빌드와 테스트가 통과하는지 확인한다.
* 커밋과 PR 생성은 사용자가 요청할 때만 수행한다.
* `.env`, 인증 정보, 빌드 산출물 등 커밋 대상이 아닌 파일은 포함하지 않는다.


### 커밋 메시지 형식

```
<타입>: <한글 설명>

<본문 (선택)>
```

**타입**

| 타입 | 설명 |
|---|---|
| `feat` | 새로운 기능 추가 |
| `fix` | 버그 수정 |
| `refactor` | 동작 변경 없는 내부 구조 개선 |
| `chore` | 빌드, 설정, 의존성 등 유지보수 작업 |
| `docs` | 문서 작성 및 수정 |
| `test` | 기존 코드에 대한 테스트 코드만 작성 및 수정 |

**작성 규칙**

* 타입 뒤에는 콜론(`:`)과 공백 한 칸을 둔다.
* 제목은 50자 이내로 작성하며, 제목은 한글로 작성하고 끝에 마침표를 붙이지 않는다.
* 제목에는 무엇을 변경했는지 대상을 구체적으로 작성한다. ("기능 구현", "버그 수정"처럼 대상 없이 동작만 적지 않는다.)
* 본문은 제목과 한 줄을 띄우고, 변경 이유를 중심으로 3줄 이내로 작성한다.

**예시**

```
feat: 회원가입 이메일 중복 검사 추가
fix: 로그인 실패 시 500 에러가 반환되는 문제 수정
refactor: 주문 금액 계산 로직을 OrderCalculator로 분리
chore: Spring Boot 3.3으로 버전 업그레이드
docs: 인증 API 요청 예시 추가
test: UserService 비밀번호 검증 테스트 추가
```

**커밋 절차 예시**

```
git checkout main
git pull
git checkout -b feat/user-signup
git add src/main/java/com/example/user/UserController.java \
        src/main/java/com/example/user/UserService.java \
        src/test/java/com/example/user/UserServiceTest.java
git commit -m "feat: 회원가입 이메일 중복 검사 추가"
```

* `git add .`, `git add -A`는 사용하지 않고 변경한 파일을 직접 지정한다.
* 커밋 전 `git status`, `git diff --staged`로 포함될 변경 사항을 확인한다.


### 커밋 단위

* 하나의 커밋에는 하나의 논리적 변경만 포함한다.
* 각 커밋은 독립적으로 리뷰할 수 있어야 한다.
* git revert 시 특정 변경 사항만 되돌릴 수 있도록 구성한다.
* 하나의 기능을 구성하는 관련 파일(Controller, Service, Repository 등)은 같은 커밋으로 묶는다.
* 기능과 함께 작성한 테스트 코드는 해당 기능 커밋에 포함한다.

### 브랜치 컨벤션

**기본 규칙**

* 모든 작업 브랜치는 최신 main에서 생성한다.
* 브랜치명은 영문 소문자로 작성한다.
* 여러 단어는 하이픈(-)으로 구분한다.

**네이밍 형식**

```
<타입>/<작업명>
```

| 타입 | 용도 | 예시 |
|---|---|---|
| `feat` | 새로운 기능 개발 | `feat/user-login` |
| `fix` | 버그 수정 | `fix/login-error` |
| `refactor` | 코드 구조 개선 | `refactor/user-service` |
| `chore` | 환경 및 설정 변경 | `chore/gradle-config` |
| `docs` | 문서 작성 및 수정 | `docs/api-guide` |
| `test` | 테스트 코드 작성 및 수정 | `test/user-service` |


### Pull Request 컨벤션

**기본 규칙**

* 작업이 완료되면 main을 대상으로 PR을 생성한다.
* PR 제목과 설명은 한글로 작성한다.
* PR 제목은 타입 없이 변경 내용을 한 문장으로 작성한다.
* 하나의 PR에는 하나의 논리적 작업을 포함한다.
* 리뷰어가 변경 목적과 내용을 파악할 수 있도록 작성한다.

**PR 제목 예시**

```
로그인 기능 구현
로그인 실패 시 예외 처리 수정
사용자 서비스 내부 구조 개선
```

**PR 본문 템플릿**

```
## 변경 내용
- 무엇을 변경했는지 작성한다.

## 변경 이유
- 변경이 필요한 이유를 작성한다.

## 트레이드오프
- 여러 선택지 중 특정 방식을 선택했다면 그 이유와 장단점을 작성한다.
- 해당 사항이 없으면 "없음"으로 작성한다.
```
