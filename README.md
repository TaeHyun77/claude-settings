### 개발 워크플로우 구축
---
AI를 활용한 개발 과정에서 일관된 작업 방식을 유지하고 관리하기 위해 개발 워크플로우를 구축했습니다.<br><br>

* AI 활용 이후 약 3배 증가한 PR의 검증 부담을 줄이고 리뷰 정확성을 높이기 위해 작업 단위를 기능별로 세분화
* 기능별 진행 상황과 의존 관계를 체계적으로 관리하기 위해 Jira에 하위 이슈로 등록
* 각 기능은 '요구사항 분석 → 계획 확인 → 구현 → 검증 → 리뷰 → 커밋' 순서로 진행<br><br>

개발 워크플로우의 각 단계에 필요한 Skill, Hook, MCP 등을 직접 구현하고 활용했습니다.<br><br>

**개발 워크 플로우**

1. 계획 수립

   * Plan 모드로 작업 계획을 작성하고 승인받습니다.
   * 승인된 계획은 docs/design/<작업>.md에 저장합니다.

3. 작업 분해
   
   * decompose-design 스킬로 설계 내용을 기능 단위로 분리하고 승인받습니다.
   * 설계 문서에 기능 ID, 작업 범위, 의존 관계, 구현 순서를 포함한 구현 계획을 추가합니다.
   * Jira 사용 시, create-jira-subtasks로 이슈를 생성하고 해당 키를 설계 문서에 기록합니다.

4. 기능별 개발

   * 작업 브랜치를 생성하고 기능 단위로 개발을 진행합니다.
   * 각 기능은 /feature-dev <설계 문서> <기능 ID>를 통해 '요구사항 분석 → 계획 확인 → 구현 → 검증 → 리뷰 → 커밋' 과정을 수행합니다.
   * 기존 계획과 달라지는 경우에만 추가 승인을 받습니다.
   * Jira 사용 시, 해당 기능의 개발이 완료되면 이슈를 완료 처리합니다.

5. 통합 및 마무리

   * 모든 기능의 커밋을 통합한 상태에서 모듈 테스트를 실행합니다.
   * 전체 검증이 완료되면 main을 대상으로 PR을 생성합니다.
